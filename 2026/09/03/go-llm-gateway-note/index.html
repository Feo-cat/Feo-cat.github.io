用 Go 写一个最小 LLM 网关：OpenAI 格式、流式转发与错误处理

发表于2026-09-03|Agent 工程
|阅读时长:19分钟
最后复核:2026-09-03|适用环境:Go 1.24.7

这篇笔记从一个空目录开始，搭建能够实际运行的最小 LLM 网关。它只使用 Go 标准库，只连接 OpenAI Chat Completions 接口，同时支持普通 JSON 响应和 SSE 流式响应。

读者只需要了解 Go 的函数、结构体和错误处理。即使还不熟悉 HTTP 代理或 SSE，也可以按顺序完成整个示例。

本教程以 Go 1.24.7 为基准。最终程序只绑定本机地址，没有调用方鉴权、限流和审计能力，适合学习与本地实验，不能直接暴露到公网。

这个最小网关只负责五件事：

  1. 从环境变量读取 API Key，不让客户端直接接触密钥。
  2. 接收 OpenAI Chat Completions 格式的请求。
  3. 为上游请求补上身份认证，然后转发原始 JSON。
  4. 透传普通响应，并实时刷新 SSE 流式响应。
  5. 为网关自身的失败返回统一 JSON 错误。

这里的“上游”是网关要访问的服务，也就是 OpenAI API；“下游”则是调用网关的客户端。

7. 区分网关超时和连接失败

client.Do 返回错误时，没有收到可以透传的上游 HTTP 响应。这类错误由网关自己生成：

三种情况的处理不同：

  • 网关超时：返回 504 Gateway Timeout。
  • 客户端主动断开：停止工作，不再尝试写响应。
  • DNS、连接拒绝等其他网络失败：返回 502 Bad Gateway。

上游已经返回的 4xx 或 5xx 不属于这段逻辑。它们是有效的 HTTP 响应，应继续透传状态码和响应体。

13. 当前版本故意没有做什么

为了让第一版保持清晰，下面这些能力没有加入：

  • 调用本地网关时的身份认证。
  • 请求体大小限制。
  • 并发限制和速率限制。
  • 重试、熔断和多上游路由。
  • 模型白名单或请求字段校验。
  • Token 用量、费用和延迟统计。
  • 日志脱敏、链路追踪和持久化审计。
  • 服务优雅退出与生产级 TLS 配置。

这些不是“不重要”，而是不适合同时塞进第一个教学示例。最自然的下一步是先加调用方鉴权和请求体大小限制，再考虑限流与可观测性。

小结

这个最小项目已经跑通了一条完整链路：客户端把 OpenAI Chat Completions 请求发给本地 Go 服务，网关安全地补上 API Key，再把普通 JSON 或 SSE 事件流返回给客户端。

实现过程中最值得记住的是三点：

  1. 只解析网关真正需要的字段，其余 JSON 原样转发。
  2. 上游已经返回的 HTTP 状态应该透传；只有网络失败和超时才由网关生成错误。
  3. SSE 不能只用 io.Copy，还需要在写入后及时 Flush。
