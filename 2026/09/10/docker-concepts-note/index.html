Docker 概念入门：程序为什么要装进容器里

发表于2026-09-10|后端与基础设施
|阅读时长:8分钟
最后复核:2026-09-10

假设你写了一个待办事项网站：打开网页，可以添加任务、勾选完成，关掉页面以后任务还在。

它在你的电脑上运行得很好。你把代码发给朋友，朋友却说：“启动不了，提示缺少一个东西。”装好那个东西，又发现版本对不上。

Docker 就经常出现在这样的场景里。要理解它，可以先从一个很朴素的问题开始：我们交付一个程序时，到底还需要一起交付什么？

这是“容器与编排入门”的第一篇。读完可以继续看 Kubernetes 概念入门。这里先建立概念，不需要提前安装软件。

代码之外，还有运行环境

一个网站通常不只是一份代码。以这个待办网站为例，它可能还需要：

  • 运行时：负责执行代码的软件，例如 Python 解释器。
  • 依赖：程序借用的现成工具，例如处理网页请求的库。
  • 配置：告诉程序监听哪个端口、连接哪个数据库。
  • 数据库：长期保存任务记录的软件。

把程序放到另一台电脑或服务器上，让它持续提供服务，这个过程通常叫“部署”。服务器在这里可以先理解成一台负责响应别人请求的计算机。

如果只复制代码，对方仍然需要重新准备运行环境。某个版本、文件路径或安装步骤不同，都可能让程序表现不同。

Docker 提供了一套构建、分发和运行容器的工具。我们可以把应用及其需要的依赖制作成统一的包，再按明确的配置启动，从而减少重复搭环境的工作。Docker 官方概述

不过，“一起打包”不意味着整个网站的所有东西都必须塞进一个包。待办应用可以有自己的容器，数据库也可以有自己的容器，两者通过网络通信。

容器：给正在执行的程序安排一个相对独立的环境

程序文件放在硬盘上时，只是一组文件。启动以后，操作系统会为它安排执行和内存资源；这样的执行实例叫“进程”。

容器可以理解成带着所需文件、在隔离环境中运行的进程。 它看到的文件、网络和其他进程，可以与宿主环境有所隔离。“宿主”指承载它的环境。

比如两个网站分别需要不同版本的 Python。它们可以使用各自容器里的 Python 和依赖，减少互相干扰；你不必为了一个项目去改另一个项目的安装环境。

容器并不是凭空多出了一台电脑。它仍然消耗实际机器上的处理器、内存和磁盘，隔离程度也受运行配置影响。Docker 对容器的解释

镜像和容器：准备好的材料，与实际启动的一份程序

理解 Docker 最值得先分清的两个词，是 Image（镜像） 和 Container（容器）。

镜像保存创建容器所需的文件和默认配置。待办应用的镜像可能包含 Python、依赖库、网站代码，以及默认启动方式。镜像本身不会处理用户请求，要从它创建并启动容器，程序才开始工作。Docker 对镜像的解释

可以把镜像想成一份准备好的课程资料包：包里有材料和使用说明。容器则像根据这份资料包实际开起来的一次课堂。

同一份资料包可以开多个班；同一个镜像也可以创建多个容器。每个容器都有自己的运行状态。这个类比只是在说明“一份模板，多份实例”，不表示容器里有完整的独立操作系统。

对比点 镜像 容器
它是什么 创建容器的只读模板 根据镜像创建的一份实例
会处理网页请求吗 不会 启动应用后才可能处理
能否有多份运行实例 一个镜像可以创建多个容器 每个容器分别启动、停止
写入新文件会怎样 原镜像不因此改变 写入容器自身的可写部分，或挂载的存储

这也解释了为什么“我改了容器里的文件”与“我更新了镜像”是两回事。应用更新通常会制作新镜像，再用它创建新容器。

Dockerfile、镜像仓库：镜像怎么制作，又怎么交给别人

假设你要把待办应用打包，可以写一份制作说明，内容大概是：

  1. 以带有 Python 的基础镜像为起点。
  2. 安装应用需要的库。
  3. 放入应用代码。
  4. 设置默认启动命令。

这份通常名为 Dockerfile 的文本文件，是交给构建工具的说明书。按它完成构建，才会得到镜像。因此，Dockerfile、镜像和容器是三个不同阶段的东西。Dockerfile 官方入门

如果想把镜像交给别人，可以上传到 镜像仓库服务（Registry）。对方再从那里下载镜像。Docker Hub 就是一个常见的镜像分发服务。

容器和虚拟机有什么区别

虚拟机可以理解成由软件提供的一台“虚拟计算机”，里面运行自己的操作系统和内核。内核是操作系统中负责管理硬件资源、进程等工作的核心部分。

通常的 Linux 容器共享承载它们的 Linux 内核，只隔离应用需要的运行环境，因此不需要为每个容器再启动一套独立内核。Docker 对容器与虚拟机的比较

关心的问题 虚拟机 通常的 Linux 容器
是否有自己的操作系统内核 有 共享承载环境的内核
启动时主要启动什么 一套操作系统及应用 应用进程
常见用途 提供独立的系统环境 打包和运行应用

两者可以一起用：一台云服务器本身可能就是虚拟机，上面再运行多个容器。

那么 Windows 怎么运行 Linux 容器？以 Docker Desktop 的 WSL 2 后端为例，中间有 WSL 2 提供 Linux 内核环境。Linux 容器并不是直接借用 Windows 内核运行。Docker Desktop 的 WSL 2 后端

所以，容器能提高可移植性，但仍有平台前提。目标环境要支持镜像对应的系统和处理器架构；数据库地址、外部文件等运行配置也仍需准备。Docker 多平台镜像说明

停止、删除、重新创建，会不会丢数据

回到待办网站。程序可以重新部署，但用户写下的任务不能每次跟着消失。

先区分三个动作：

  • 停止容器：程序不再运行，容器本身仍然存在。
  • 重新启动同一个容器：继续使用这个容器已有的文件状态，内存中的临时状态不会保留。
  • 删除后重新创建容器：得到一个新实例，旧容器自身可写部分里的文件不会自动跟过来。

因此，“容器一停止，里面所有文件就消失”是不准确的。真正需要警惕的是：把长期数据只放在会被删除的容器可写部分里。Docker 的容器存储说明

数据卷（Volume） 用来把需要保留的数据放到独立于容器生命周期的存储中，再挂载给容器使用。“挂载”可以先理解成：让容器通过某个目录访问这份存储。

这样，即使替换了数据库容器，只要数据卷仍保留、重新挂载到正确位置，并且数据库版本兼容，就可以继续使用原来的数据。Docker 数据持久化说明

数据卷也占用真实磁盘，并不等于自动备份。保留文件、备份文件、让多台机器共享文件，是不同的问题。

容器里的网站，浏览器怎么访问

网站已经启动，浏览器却不一定能直接访问它。这时还要理解 端口。

如果把一台计算机的地址看成一栋楼的地址，端口就有点像楼里的分机号码：网络请求到达机器后，还要知道交给哪个监听程序。

Dockerfile 中的 EXPOSE 80 只是说明应用预计使用哪个端口，不会自动完成上述发布配置。Docker 端口发布说明

Docker Compose：把一个应用的几个容器组织起来

待办网站现在可能有两个主要部分：处理请求的应用容器，以及保存记录的数据库容器。你需要告诉它们怎样联网、使用哪些配置、把数据放在哪里。

Docker Compose 可以把这些运行配置写到一份 YAML 文件里，统一管理这组服务。YAML 是一种用缩进表达层级的文本格式，先把它当作“机器能读懂的配置清单”即可。

Dockerfile 描述怎样制作镜像；Compose 文件描述一个应用由哪些服务组成，以及它们怎样运行。Compose 也可以引用 Dockerfile 来构建其中某个服务的镜像。Docker Compose 官方入门

对这个小网站而言，清楚描述应用和数据库的组合方式，已经能省去许多重复操作。等到还要处理多台机器上的调度、故障替换和持续更新时，就会接触下一篇的 Kubernetes。

用三个问题检查一下理解

下载好了镜像，网站就已经运行了吗？

还没有。镜像只是准备好的文件和配置，需要创建并启动容器，让里面的程序开始工作。

从同一个镜像启动两个容器，它们会自动共享新写入的文件吗？

不会。它们是不同实例；共享数据需要明确的存储或网络安排。

使用了 Docker，还需要关心数据库和配置吗？

需要。Docker 帮助你一致地交付和启动应用，但数据库连接、数据保存位置和网络访问仍属于应用运行的一部分。

带着这三个答案，再读 Kubernetes 概念入门：容器多了以后，谁来照看它们，会更容易理解为什么还需要另一层管理工具。
